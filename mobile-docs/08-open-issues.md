# 08 · 风险、决策与待核实项

下列问题在开工或对应阶段进入前核实。能依据当前代码安全确定的规则已写入规范；这些待核实项不授权修改桌面或生产后端。

## 发布前必须核实

1. **目标工程位置与包标识**：Flutter app 放在仓库 `mobile-app/` 还是同级独立 repo？iOS bundle ID、Android applicationId、签名由谁管理？默认建议此仓库独立 `mobile-app/` 子目录，避免文档与源码混放。
2. **PocketBase 部署安全**：当前桌面默认 URL 是 HTTP。确认生产环境是否有 HTTPS、证书、限流、备份、版本和升级窗口。不得在移动发布中静默改 URL 或把用户密钥写入客户端。
3. **实际 schema 与 API 兼容性**：使用测试用户只读核对现有 `configs` 与 `sync_*` collection 字段/Rules/索引；验证较新的移动 serializer 能否被当前桌面完全读取。禁止用 superuser key 发客户端请求。
4. **移动端首次接管策略**：桌面本地可以先含 demo seed。对一个已存在本地资料、同时云端非空的场景，确定是否采用明确的接管/合并预览，而非静默“rev 胜者”。保护本地备份的保留周期需要定案。
5. **配置快照的并发范围**：当前 `configs` 是整份快照 LWW；两台离线设备分别改设置的不同域，可能丢一边修改。移动端先兼容现有协议；是否升级为域级合并需要桌面/移动共同方案和用户决策。
6. **奖励账本多端并发**：`growth_data` 在 config snapshot 中整份同步。确认并发兑换/会员确认是否有跨设备原子结算/幂等保障。未证实前可提示单设备完成付款/兑换确认，但不能擅自改账本协议。
7. **同步删除与时钟**：行级 LWW 用客户端 `updated_at`，桌面有 PB 游标和 tombstone。实测时间偏差、删除/编辑竞争和事务提交顺序；不得因设备时钟错误复活数据。
8. **Flutter/原生工具版本**：明确 Flutter stable、Xcode/Swift 最低版本、Android Gradle/SDK、最低 OS 和 CI runner，再锁依赖版本。

## 移动 OS 能力边界

- iOS 不允许任意常驻后台任务；Android 精确闹钟/前台服务均有版本、用途声明和用户授权限制。计时应恢复准确，通知需按平台机制，不应承诺应用关闭后进程持续运行。
- iOS 与 Android 系统小组件各自开发、刷新频率和交互能力不同。复用当前 macOS WidgetKit 工程不可直接得到移动组件。
- 相册资源若本地自定义壁纸需要离线显示，需明确文件拷贝与备份/同步策略；现桌面 `wallpapers` 在 configs 里可能含 data URI，需确认 payload 大小限制。
- 白噪音与结束提示在后台/锁屏时会受系统音频会话和用户静音策略影响；以真实设备测试为准。

## 需保持诚实的当前已知边界

- 桌面 docs 记载单设备同步做过端到端测试，多设备并发未压测。移动端上线前必须补跨平台并发和压力测试。
- PocketBase Realtime、配置整快照和多端奖励结算的可靠性不能由 mock 验收证明。
- 头像文件目前服务端公开 URL 可读。若此隐私边界不可接受，应先规划兼容桌面的后端权限改造，不能只在 Flutter 隐藏链接。
- 当前支付为静态收款码 + 用户手动确认；不是支付 SDK 回调，也不是自动对账。
- 移动端“与桌面功能相同”不代表把桌面窗口控件搬到手机。功能等价需在平台矩阵里逐项给出替代交互和验收证据。
