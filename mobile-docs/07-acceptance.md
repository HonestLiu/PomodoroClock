# 07 · 验收与测试矩阵

## 完成定义

每个功能只有在以下条件全部满足后才能标为完成：

- 符合 `02-product-parity.md` 和相应桌面模块的业务规则；中英文本完整。
- 本地模型/API DTO/schema migration 落地；失败、空、离线状态可用。
- 至少有 domain 单测、repository/sync 测试和关键 Widget 测试。
- iOS 与 Android 至少各一次真实构建；涉及原生能力的功能在真实设备验证，不以模拟器替代通知/音频/后台验证。
- 涉及同步时执行桌面与移动真实账号交叉验证，并记录设备、服务端环境及证据边界。
- 更新路线图、已知问题和相关数据/功能文档；不留只在 UI 上工作的 mock 操作。

## P0 数据与账号

- [ ] 未登录离线创建任务/专注记录，重启后仍在。
- [ ] 新设备登录有云数据时先拉取；演示种子不能覆盖云数据。
- [ ] 同一用户桌面→移动、移动→桌面同步任务字段、清单、记录、共享设置、奖励/任务线/倒数日/通知。
- [ ] A/B 两端离线修改同一配置快照后按兼容协议收敛，用户可见胜者和备份/提示明确。
- [ ] 账号 A 登出后账号 B 登录，不串读/串写数据或游标；登出不清本地数据。
- [ ] 移动端删除任务/清单后，桌面端同步删除；记录关联按规则置空；旧设备不能复活墓碑。
- [ ] 网络中断、超时但服务端成功、重复请求、Realtime 回声均幂等；游标不漏/跳过数据。
- [ ] `ai_api_key`、`pb_url`、当前计时和设备权限从 PB 请求 payload 中排除。
- [ ] 同步中断/认证过期时本地仍能工作；重登录可恢复 outbox。

## P0 计时与奖励

- [ ] 三种计时模式语义、暂停时长、跳过、关闭/重启恢复与桌面规则一致。
- [ ] 后台/杀进程后 elapsed 由绝对时间计算；系统通知是否能准时受权限/OS 限制，状态诚实显示。
- [ ] 同一会话仅生成一条记录、一条奖励结算；跨端重放/恢复不重复发金币/XP。
- [ ] 倒计时结束不写 focus record；专注结束写正确时间段；休息不计入记录。
- [ ] 白噪音、来电/音频焦点中断、停止和恢复行为无残留播放。

## P1 功能覆盖

- [ ] `02-product-parity.md` 每行均逐项完成，包括任务字段和视图、搜索、报表周期/统计、AI 四能力、任务线、倒数日、奖励中心、设置和通知。
- [ ] 重复任务跨小时/日/周/月底和时区边界符合桌面规则，操作幂等。
- [ ] 报表同一测试数据在桌面和 Flutter 每项数值相同（含今日/本周边界、DST、闰年、无效/未来/休息记录）。
- [ ] 自定义图/头像/二维码上传类型与大小受限；取消/失败不丢原资源。
- [ ] AI 调用取消、超时、JSON 失败和无 key 时均能回退；未确认草稿不会写入业务数据。
- [ ] 会员二维码流程如实标注用户自觉确认、不冒充已验证支付；同一订单多次点击只入账一次。

## P1 可用性/设备

- [ ] iOS/Android 小屏、横屏、刘海、软键盘、系统大字体、深浅色、中英文、屏幕阅读器。
- [ ] 快速连续操作、页面切换、杀进程、低内存恢复、时区更换、夏令时变化。
- [ ] 通知权限允许/拒绝/撤销；系统省电模式、后台限制、网络从 Wi-Fi 切移动网络。
- [ ] Release 构建不含管理员凭据、测试 token、硬编码开发密钥；日志无隐私 payload。

## 同步证据格式

每次跨端验收记录：移动版本/commit、桌面版本/commit、OS/机型、PocketBase 环境（仅环境名，不写敏感 URL/账号）、测试用户隔离方式、前置数据、操作步骤、期望/实际记录、失败和重试情况、通过范围。静态 mock、fake server、单元测试只能证明相应层，不可称真实跨设备已验证。

## 自动化建议

- Domain：计时状态机、奖励幂等、周期边界、冲突排序、DTO 白名单、墓碑收敛、接管决策。
- Repository：SQLite rollback、outbox atomicity、分页/游标、远端重复响应、切账号隔离。
- Widget：关键页面加载/空/离线/确认/错误/窄屏/大字体。
- Integration：登录接管、离线队列、真实 PocketBase 测试实例、桌面联调、后台恢复。CI 使用独立可销毁测试用户与数据，不接触生产数据。
