# 01 · 项目约定与 Codex 实现指令

## 任务目标

实现一款独立的 Flutter iOS / Android 应用 **FocusPomodoro**。功能以桌面当前实现为准，支持中英文、浅色/深色、离线优先、同 PocketBase 用户登录和跨设备数据同步。移动端是新客户端，不是桌面网页的 WebView 包装。

## 开始任务时

1. 检查仓库 `git status`，不得覆盖或清理用户已有修改；只修改移动端工程及本目录文档，除非用户明确授权改桌面端或服务端。
2. 阅读 `mobile-docs/README.md`、本指令、同步契约、桌面 `CLAUDE.md`、模块索引、`docs/03-architecture.md`、`docs/04-data.md`、`docs/09-sync-server.md` 和同步实现源码。
3. 探测 Flutter、Dart、Xcode、Android SDK、当前 PocketBase base URL 配置与集合结构。只记录是否可用，不输出 `.env.local`、令牌、支付二维码或个人资料。
4. 先报告工程目录、架构草案、同步方案、功能拆分和未知项，再开始跨阶段的大规模改动。无需为一般文件编辑反复请求确认。
5. 如果桌面代码与文档冲突，以当前运行代码和服务器 schema 为事实，写下差异及出处，再继续。

## 实现红线

- 新建独立 Flutter 工程，建议目录 `mobile-app/`，Android/iOS 原生工程均纳入版本控制；不要替换根项目的 Vite/Tauri 构建链。
- 所有业务访问走 repository / service 层；Widget 不直接读写 SQLite、PocketBase 或 SharedPreferences。
- 本地数据库是离线工作源。数据库写入成功后 UI 即可更新，同步作为可重试后台流程；远端错误不能回滚本地操作。
- 不调用超级管理员 API；不得把 PocketBase superuser 凭据、静态管理员令牌、生产密码写入客户端、文档、测试数据或日志。
- 使用既有 PocketBase URL、`users`、`configs` 和同步集合。不得建第二套账号、另起云数据库或修改现有集合字段/访问规则来迁就客户端；若发现必要 schema 缺口，先写提案，不直接迁移生产库。
- 远端同步 payload 必须按集合白名单序列化。特别排除 `ai_api_key`、`pb_url`、`timer_state`、设备通知权限、文件本地路径和仅本机密钥。
- 远端数据先验证、归一化、事务落库；单条坏数据应进入可诊断错误路径，不得清库或导致整库部分提交。
- 计时以绝对时间戳推导。禁止用周期 tick 累加已过时间；后台暂停/进程终止/重启均不得凭空丢失或多结算记录。
- 奖励账本必须复用桌面业务规则并保证幂等；不能为了 UI 动画直接改余额。
- AI 结果必须先成为草稿，用户确认后才写任务；未配置/断网时保留手动路径。
- 隐私数据不写 debug 日志：密码、token、邮箱、备注正文、API Key、二维码、头像内容和同步 payload。
- 新功能必须有逻辑单测、repository/API 测试、Widget/集成测试。模拟测试不能代替真实 PocketBase 与真实设备验收；报告证据边界。

## 实现质量

- 使用稳定 Flutter/Dart 版本；依赖选择说明原因并锁定版本，避免没有必要的插件堆叠。
- 使用强类型模型、可测试纯函数、明确错误类型、数据库迁移和结构化日志（脱敏）。格式化、静态分析和测试纳入阶段验收。
- 重要操作支持加载、空、错误、离线、同步中、同步失败、重试和成功反馈。
- 页面适配小屏、键盘、系统字体缩放、屏幕阅读器、刘海/安全区和横竖屏；表单与对话框不超出视口。
- 中英文词条完整成对；日期和“今天/本周”边界按用户设备本地时区计算，但跨端时间戳保存 UTC 毫秒。
- 不将 Web 桌面截屏作为移动端最终 UI；重新设计触屏操作，但保持可理解的桌面语义。
