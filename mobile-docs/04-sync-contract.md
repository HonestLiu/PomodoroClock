# 04 · 数据模型与 PocketBase 同步契约

本文件是跨设备数据一致性的核心规范。任何字段或集合细节不确定时必须查看当前 PocketBase schema 与桌面端 serializer；不得只从本文推断缺失字段。

## 后端与身份

- 使用桌面运行时相同的 PocketBase base URL。当前解析顺序为本机 `settings.pb_url` → 构建时 `VITE_PB_URL` → 内置默认 URL（见 `docs/09-sync-server.md`）。生产部署值部署时复核，不将示例凭据复制到移动包。
- 账号使用现有 `users` 认证。登录/注册/改密码/重置密码/昵称/头像遵循 `src/lib/pb.ts` 与 `authStore.ts` 行为；邮箱不可在客户端直接改。
- `configs` 每用户一条；数据实体的 `user` 字段必须等于当前已认证用户。PocketBase 规则限制用户只能读写自己的记录；客户端仍检查返回记录的 owner。
- 客户端禁止使用 superuser API 或管理员凭据。

## 集合映射

| 本地数据 | 云端 | 同步策略 |
|---|---|---|
| 清单夹 | `sync_folders` | 行级增量、墓碑删除 |
| 清单 | `sync_lists` | 行级增量、墓碑删除；依赖 folder |
| 任务/子任务 | `sync_tasks` | 行级增量、墓碑删除；依赖 list/parent |
| 专注记录 | `sync_records` | 行级增量、墓碑删除；记录引用任务和清单可空 |
| 共享设置、默认清单、奖励账本、倒数日、任务线、应用内通知 | `configs.data` | 单账号快照；遵循桌面 DTO 和 `rev/updated/device` 裁决 |
| 头像、昵称、邮箱、密码 | `users` | PocketBase 账户资料 API；不放入 configs |
| 当前计时会话、`ai_api_key`、`pb_url`、权限/播放状态 | 本机 | 不同步 |

### 行级公共字段

桌面集合 setup 当前定义：`user`（关系）、`local_id`、`deleted`、`updated_at`、`created_at`、`updated`（PB 自动时间）。唯一索引 `(user, local_id)`。任务与其他字段定义以 `scripts/pb-sync-setup.mjs` 的字段列表为准。包括 `sync_tasks` 的 URL、标签、重复、提醒、层级、完成状态等列；专注记录的 phase、起止、时长等列。

移动端实现 PocketBase DTO 时，保留本地 ID 为 `local_id`，不要用 PB record id 替换桌面主键。日期/数组/布尔值/数值在 JSON 与 PocketBase text/number 字段间必须遵循桌面 serializer 约定；不允许凭字段名称猜类型。新增字段需先确认桌面和服务器 schema 兼容策略。

## 首次登录和账号切换（P0）

必须先实现“接管门闩”，测试通过前不得启用自动推送：

1. 未登录时允许本地完整工作，业务数据保留在本机。
2. 用户登录后先检查该账号的 `configs` 与四类业务集合，完成只读拉取/统计；本地也统计可同步行、演示数据标记、当前登录账号最后同步身份。
3. 对于空白设备且远端已有数据：先拉远端，再开放正常写操作；不能先显示演示种子并推送覆盖远端。
4. 对于已有本地数据且远端已有数据：按桌面已有冲突机制自动裁决，并向用户说明“本机数据/云端数据”将如何合并或覆盖。不得做无确认全量替换。
5. 对于远端为空：只在识别本地数据归属、用户确认后首次推送；若本地是未确认 demo seed，则默认不推种子，先提供清空演示/保留并导入选项。
6. 账号切换时先暂停同步、刷新并安全保存旧用户 outbox；新用户视图必须隔离。不能把用户 A 的本地数据推入用户 B 的账号。
7. 接管决策和 schema 兼容校验成功后写 `sync.bootstrap.<userId>` 成功标记。中途失败可幂等重试。

当空远端但本地业务数据同时有多个用户历史时，阻止自动推送并让用户选择；不得根据当前显示昵称猜数据所有者。

## 配置快照

现有快照 `configs` 规则来自 `src/lib/sync.ts`：`data` 携带 Settings 白名单、`default_list_id`、`quest_data`、`countdowns`、`notifications`。奖励账本作为 `settings.growth_data` 中的版本化 JSON 共享。`ai_api_key` 和 `pb_url` 必须删除/排除；`timer_state` 不属于 configs。

远端字段包含 `user`、`data`、`rev`、`device` 和 PB 自动 `updated`。裁决顺序：

1. 本地无远端记录：待接管规则许可后 push。
2. 本地无同步元数据：优先 pull（但先执行本地/云端接管确认，不得覆盖本地重要内容）。
3. 比较 `rev`；大者胜。
4. `rev` 相同，按 PB `updated` 字符串比较。
5. 仍相同，按 `device` 字典序确定胜者；设备相同或同一写入则 none。

桌面端是整份快照的最后写入胜者，离线时同时编辑两个不同设置域仍可能整份覆盖。Flutter 必须兼容该协议；可在本地增加草稿/冲突备份，但不能仅在移动端发明另一个胜者算法。发布前须做并发检查；若需改成域级合并，必须先做桌面兼容设计并获得用户确认后同步改两端。

## 行级同步

桌面当前协议（`src/lib/syncData.ts` 与 Rust `commands/sync.rs`）要点：

- `sync_dirty` / `sync_tombstones` 记录本地变更和硬删除墓碑，应用层不逐个业务按钮调用同步。
- 先按依赖顺序拉取/推送：folders → lists → tasks → records。
- 批量上限桌面当前为 80；游标按 PocketBase 服务端 `updated`，不是设备墙钟，防止时钟漂移漏数据。
- 按 `local_id` 找云端行，唯一键 `(user,local_id)`；维护 PB id shadow 可加速，但换机必须可回查。
- 更新冲突按行 `updated_at` 毫秒 LWW；桌面当前平局时远端优先。墓碑传播后各端本地硬删；较新的远端墓碑不可被旧本地行复活。
- 拉取的外键依赖缺失时按桌面规则置空或延迟重试；不能因一条孤儿记录整批半提交。
- 拉取先应用远端，再推本地 dirty；游标安全回退小窗口并保证幂等，具体值以桌面运行代码为准。
- 每账号、每集合独立游标；同步提交数据与游标前确认本批事务完整成功。

Flutter 可以在本地用 durable outbox 实现等价同步，不能要求远端增加桌面没有的必填字段。同步事件不重复写入另一条专注记录或奖励事件。

## 离线、Realtime 与恢复

触发同步：首次账号接管、启动/登录、前台恢复、网络恢复、本地 outbox 防抖、Realtime 事件、用户手动刷新和后台允许时的周期任务。实时订阅仅减少延迟；订阅挂断必须被轮询和恢复同步弥补。指数退避、随机抖动和可取消任务避免电量/网络风暴。

“已同步”只在队列确认成功时显示；另显示最后成功时间、待上传数/待下载状态、错误与重试。无网络时标为离线/待同步。认证过期要求重新登录，但本地仍可用。服务端结构不兼容时暂停受影响数据域，不可用旧 DTO 大量覆写。

## 删除和幂等

- 每个删除产生稳定墓碑，直到服务器确认且不会被仍有效游标跳过。
- 任务/清单级联按桌面定义执行，专注历史引用变 null 而历史仍保留。
- 同步重复投递、请求超时但服务器已成功、Realtime 回声、恢复启动都不得创建重复 `local_id`、下一轮重复任务、记录、奖励、支付订单入账。
- 奖励流水和支付确认使用已有稳定事件/订单 ID；是否支持多端并发购买状态以 `growth.md` 和实际 growthStore 为准，未核实前不得并发改同一账本。

## 安全与隐私

- token 只存系统安全存储；登出时移除 token 与用户会话，不清业务数据库。
- 不同步密钥、服务端 URL、运行态、路径或权限；不把日志/崩溃报告发给未配置的第三方。
- PocketBase avatar 文件当前公开文件 URL 可直接读，按 `docs/03-architecture.md` 的隐私现状处理；移动 UI 不把头像 URL 当授权凭据。
- 所有上传校验 mime、大小与解码结果；服务器仍作最终限制，失败保留本地旧头像/图片。
- 生产服务器必须 HTTPS。默认明文 HTTP URL 仅为当前兼容默认值，正式发布前核实部署 TLS 和证书；不得私自更换后端。
