# 06 · 开发阶段与交付路线

按顺序交付可运行的真实增量。每阶段结束运行对应测试并更新状态。阶段可拆小 PR/提交，但不能以 mock 代替实际实现。

## M0 · 现场勘察与工程基线

- 记录 Flutter/Dart/Xcode/Android SDK 版本、构建目标、项目路径和仓库既有改动。
- 核对 PocketBase 当前 collections、rules、users 认证字段；检查 `configs.data` 与同步 DTO 当前 schema。
- 明确目标 iOS/Android 最低版本、包 ID/签名持有人、生产/测试 base URL 的注入方式。不要创建或改生产数据。
- 创建独立 `mobile-app/` Flutter skeleton、格式化/lint/test CI 命令、flavor 配置；不要提交 secret。
- 交付：架构决策记录和可在两平台构建的空壳。此阶段不称功能完成。

## M1 · Domain、数据库和基础 UI

- 建共享模型、数据库 schema 与迁移、Repository、日期/时区工具、主题、中英文、导航和设计令牌。
- 先复现任务、清单、专注记录、设置、通知、倒数日等桌面字段和枚举，加入 serializer contract tests。
- 建本地 seed/空账号数据策略，演示数据不得混入账号首次推送。
- 交付：离线浏览和数据库迁移测试通过。

## M2 · 账户与安全

- 接入既有 PB auth：注册/登录/忘记密码/改密码/昵称/头像、登出及认证恢复。
- 安全存储 token；落实跨账号本地隔离方案、登出保留和本机清除流程。
- 交付：真实测试账号可登录/恢复；不碰管理员 API。

## M3 · 同步引擎先行

- 先实现 bootstrap/接管门闩、行级 DTO/游标/dirty/outbox/墓碑、配置快照 rev 冲突、离线恢复/Realtime/手动同步。
- 使用隔离的测试用户和现有 PocketBase 测试环境；不在真实用户账号做破坏性冲突测试。
- 先用桌面→移动、移动→桌面、两移动设备的同步契约测试，再开放其它写功能。
- 交付：离线创建→恢复同步、两端编辑冲突、删除传播、空设备接管无数据覆盖。

## M4 · 核心闭环

- 任务、清单、分类、搜索和完成归档。
- 三模式计时、恢复/幂等记录、通知、奖励结算基本闭环。
- 交付：真机杀进程/重启/前后台测试，桌面可以读到手机新任务和记录。

## M5 · 完整业务覆盖

- 完整报表、今日面板、任务提醒/重复、倒数日、任务线、AI 草稿流程、奖励中心/会员/基金/支付二维码、账户完整设置、主题/壁纸/白噪音。
- 每模块遵守桌面 docs 的数据和验收口径；UI 窄屏适配完成。
- 交付：本文件 `02-product-parity.md` 的必需项均有平台标记和证据。

## M6 · 稳定性、可访问性和发布

- iOS 与 Android 真机回归；网络切换、弱网、重复同步、账号切换、时区/DST、通知权限、音频中断、图片上传、系统返回和大字体。
- 权限说明、隐私清单、构建 flavor、签名、崩溃日志脱敏、商店素材/版本号策略。
- 若实现系统小组件，分别维护平台专属扩展与刷新机制；不阻塞核心功能验收。
- 交付：两平台 release build、已知限制列表、验收矩阵中 P0/P1 通过。

## 不得跳过的依赖顺序

```text
契约勘察 → 本地数据/模型 → 账号安全 → 同步接管与合并 → 核心功能 → 全量功能 → 真机/发布
```

先画页面后补同步、先让演示数据上云再补接管保护、先用一台手机自测后宣称跨端一致，均不符合交付要求。
