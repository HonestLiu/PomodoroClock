# 模块 · 成长 / 账户 / 云同步（growth）

## 奖励中心（2026-10-30）

顶栏奖杯入口展示当前等级与金币，打开「激励商店 / 等级奖励 / 基金与规则 / 收支明细」。原有四项成就进度保留在等级奖励页折叠区。

- **获取**：首次启用建立历史记录基线，不追溯发放历史/演示收益。此后新归档的 `phase=focus` 按有效时长累计秒数；每 60 秒获得 1 金币，每 6 秒获得 1 XP，余数保留。暂停/休息不奖励；归档 ID 去重，重载/同步回声不重复入账。
- **等级**：Lv.1=0 XP；达到 Lv.L 的累计门槛为 `300 × L × (L−1)` XP，例 Lv.2=600、Lv.3=1800。领取不扣经验。
- **会员价估值**：用户填写奖励名称、会员价、可选普通价、说明；默认 10 金币=¥1，可在隐藏的奖励计划管理页设 1–10000 金币/元。商店所需金币为 `ceil(会员价分 × 每元金币 / 100)`，基金支出等于会员价。展示对应专注分钟及普通价节省额。估值规则变更只影响后续兑换，历史流水保持价格快照。
- **基金**：奖励专用账户对应的人民币奖励预算。会员购买金额全额入账；基金充值也通过双收款码扫码、自觉确认后入账；取出仅作预算扣账，商品仍由用户自行购买。资金去向由配置的收款码决定，不接入银行或支付平台接口。
- **兑换**：商店同时检查金币与基金余额；等级奖励要求达到指定等级并具备足额基金，不扣金币，同一目标等级仅领一次（删除后重建也不能重复领）。缺少余额时保留奖励，补足后可兑换。
- **持久化**：`settings.growth_data` 保存版本化 JSON（累计秒数/已处理 ID/金币消费/基金/估值规则/自定义奖励/流水/会员到期时间/收款配置/支付订单）。通过现有 API 在 SQLite 与 IndexedDB 中持久化，无破坏性迁移。账本只在本机，不上传或接收云配置覆盖；清空应用数据同时清空账本。
- **一致性**：所有账本操作排队，重新读取最新账本、结算专注并检查余额后整笔写入；写库成功才发布新余额。读取或结构校验失败不覆盖原数据。

### 验证

- `tools/verify-growth.ts`：33 项纯逻辑检查，含时长累计、历史/休息排除、幂等、会员价取整、余额不足、等级门槛、重复领取与 JSON 重启恢复，以及扫码订单、全额入账、重复确认、取消、续期、月末和闰年处理。
- `tools/verify-growth-ui.mjs`：Vite dev 服务下检查表单、基金、真实 API 归档收益、兑换确认、等级领取、重启、明细、深色/英文/窄窗、Esc、并发兑换、保存失败、清空数据。沿用仓库截图脚本的本机 Playwright/Chrome 路径。
- Rust `growth_ledger_settings_roundtrip_and_clear`：账本设置加载、JSON 返回与清空。

## 会员购买与扫码充值（2026-10-30）

- **入口**：顶栏皇冠、设置→会员共用 `MembershipPanel`；基金与规则页可充值；收款配置在「设置→关于→高级选项→奖励计划管理」，日常会员和基金页面不展示配置入口。
- **方案**：只提供周会员和月会员，移除年度及终身。默认 ¥6/周、¥18/月，可在隐藏管理页修改价格。每笔会员款全额计入基金，不扣平台服务费。
- **有效期**：周会员增加 7 个本地日；月会员增加 1 个月，同日超出目标月末则取月末（含闰年）。有效会员从原到期日顺延，已到期则从确认付款时起算。手动续费，不自动扣款；到期不清空基金，不影响已获取的金币/经验。
- **二维码配置**：本机上传 WeChat/Alipay 两张静态收款图片，支持 PNG/JPG/WebP，每张≤2 MB；账户说明≤200 字。实际奖励专用银行账户及关闭手机提醒由用户自行设置，应用不配置或校验银行账户。两张二维码配置好后才能发起付款。
- **支付流程**：点击方案支付/基金存入→创建本地待确认订单→同屏展示两张二维码与准确金额→用户任选扫码并手动填写金额→点击「付款成功」。不查询/核验支付结果，无论用户是否真的支付，都按订单金额认定已到账。确认前/取消后均不增加余额。
- **订单一致性**：本机同时只保留一个待确认订单；金额按下单时快照保存，待确认期间不允许更换收款设置。确认按订单 ID 幂等，会员有效期、基金余额及流水一次写入。关闭/取消/Esc 标为取消，重启则自动恢复尚未处理的待确认订单。支付面板位于专注层之上，恢复待付款时不自动展开专注层。
- **兼容**：旧版账本缺少支付字段时补默认配置，不清空原余额、商品或历史；收款码、会员期限和订单均随 `growth_data` 在本机持久化，不同步云端。
- **验收**：`tools/verify-payments-ui.mjs` 覆盖旧账本兼容、上传、双码展示、周/月方案、取消、重启恢复、无校验确认、重复点击、续费、全额入基金、扫码充值、历史、深色/英文/窄窗与清空数据。
