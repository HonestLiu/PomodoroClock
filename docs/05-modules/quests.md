# 任务看板与目标任务链（第一期）

2026-11-01。产品讨论背景见 `../09-life-game-proposal.md`；本文件描述已实现的第一期行为。

## 用户流程

侧边栏“任务看板” → 建立目标，填写当前基础、条件及每日时间预算 → AI 生成有前置关系的行动路线 → 自动发布当前已解锁、预算可容纳的任务 → 用户自行接取 → “今天”出现“已接取·今日有效”任务 → 勾选完成后正式归档并获得奖励。

未配置 AI 或离线时可选择“手动编排任务链”，每行一步、按顺序解锁，每项默认最多 25 分钟且不超过预算。AI 调用失败保留表单及错误，不凭空发布假路线。目标规划可以取消。通用设置的启动页可选择任务看板。

看板展示全部本期已发布任务及当日已接取/完成反馈。未解锁任务不在看板、普通搜索、通知或原有 AI 任务上下文中出现。目标只显示已完成行动数，不显示完整隐藏任务链。

## 生命周期和口径

- 看板任务、接取尝试与普通 tasks 独立。接取时不会创建普通任务；今天页面额外合并有效的临时待办；今天的待办数、侧边栏角标和预计投入包含这些临时任务，普通总览的数量与统计不包含。
- 每次接取锁定当地下一次午夜的失效时间。每次操作及持久化提交时均校验失效时间；跨日、唤醒、启动自动收回过期尝试。
- 未接取或未完成的任务没有普通逾期项；必要步骤保留，按后续日期重新发布。每次重新接取使用新的 attempt ID。
- 只有完成才解锁后置资格；按容量择时发布，不承诺完成前置后立即显示后置。每个目标每日最多发布三项，发布估时总量不超过目标预算，并考虑已有普通今日任务的预计投入。
- 看板任务的番茄钟/正计时专注先写暂存会话。未完成时，普通记录、报表、热力图、组件、经验和金币均不计入。普通手动任务仍沿用既有计时与结算规则。
- 完成时，只将**本次成功接取**的专注记录转入普通记录，失败的历史尝试不累计；保留真实时间戳。与现有正式记录接口一致，以完整分钟计入，不足一分钟不归档。
- 完成归档、记录转入和游戏奖励状态原子提交。同一任务仅一次有效结算。重复请求、并发窗口、过期完成均不能重复发奖。
- 已归档游戏任务通过“已完成”和今天的完成区查看，不能使用普通任务的取消完成/编辑/删除入口，防止破坏依赖和奖励。普通任务操作不受影响。
- 游戏专注到期或结算失败不得退化成“未指定任务”的正式专注。跨午夜仍绑定失效任务时停止该任务计时。
- 暂停目标停止新的发布和接取，已经接取的任务当天仍可完成。可随时继续发布。

## 奖励与兼容

每项固定任务奖励在发布前确定：金币 `ceil(预计分钟 / 10)`，范围 1–10；经验 `预计分钟 × 2`，范围 10–100。模型不能指定金额。成功接取的专注转入正式记录后，再沿用既有专注奖励，因此任务成果奖励与专注投入奖励可叠加。

奖励中心从当前游戏账本派生任务奖励，叠加既有专注收益，不修改原金币兑换率、已领取奖励或会员基金。新游戏余额支持现有商店兑换；不自动兑换或移动现实资金。

## 存储和并发

- 纯规则：`src/lib/quests/model.ts`；模型规划：`planner.ts`。
- 应用状态与发布器：`src/stores/questStore.ts`；看板：`QuestBoard.tsx`；今日临时待办：`QuestToday.tsx`。
- 新增 `quest_load` / `quest_commit` API。前端按 revision 比较并交换，遇其他窗口先提交则读取新状态重算，最多重试三次。
- SQLite：独立 `quest_state` 表保存版本化 JSON；事务内校验并创建新完成的普通任务/专注记录，再写入新版本。清空所有数据时同时清除。读取不发送到云端。
- IndexedDB：现有 kv 数据中增加可选的 `quest_data`，不升级会清库的旧 DB_VERSION。readwrite 事务内读取最新版本并创建档案；保存失败抛出错误，不显示成功。普通延迟写入会保留其他窗口已提交的更新游戏状态及其档案。
- 暂存计时绑定使用独立 `quest-attempt:` 前缀；正式档案和记录使用稳定来源 ID。普通记录 API 拒绝游戏绑定和游戏档案，避免提前入账或向已结算任务追加专注。
- 游戏本体与任务奖励首版本机保存；完成后生成的普通档案沿用现有正式任务/记录机制。尚未实现多设备目标及游戏账本同步。

## 主动运行的实际范围

启动、窗口重新可见、获得焦点及运行中每 15 秒进行确定性巡检，不在每次 tick 调用模型。模型在建立目标时生成路线，后续根据缓存路线及依赖自动发布。软件退出期间不后台调用模型，启动后仅恢复当天。

本期尚不包括：路线耗尽后的自动续写、基于困难反馈重新规划、跨设备游戏进度合并、剧情地图、装饰系统或应用退出后的后台规划。这些仍归后续阶段。

## 验证

- `node tools/verify-quests.mjs`：依赖、循环/未知引用、预算、重复接取、专注暂存、跨日重发、成功接取独立统计、奖励，并生成双端共享的合法状态 fixture。
- `cargo test --test quests`：SQLite 的事务归档、CAS、过期拒绝、奖励字段校验、正式统计、档案锁定及清空恢复。
- `node tools/verify-quests-ui.mjs`：使用独立 Chrome 测试上下文验证真实计时→暂存→跨日收回→重新接取→今日完成→正式归档→重启→后置显现；中英文、深浅色与窄窗截图。
- UI 测试需使用新启动的 Vite 服务，避免开发热更新的带时间戳模块与测试动态 import 产生两份 store。
