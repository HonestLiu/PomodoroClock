# FocusPomodoro 规范与开发文档合集

> 一组**可执行**的规范/规划文件，是顶层 `CLAUDE.md`（产品 PRD v1.0）的工程化展开。
> 与 CLAUDE.md 的关系：**CLAUDE.md 定义"做什么"（需求与口径），本目录定义"怎么做、做到什么程度、下一步做什么"**（工程规范、模块细节、路线图、验收）。
>
> 原则：凡标「当前已实现」的条目，以实际代码为准；标「待办」的条目即本期进度的验收输入。文档与代码冲突时，**以代码为准并回改文档**（§7 持续同步）。

## 阅读顺序

| 顺序 | 文档 | 内容 | 谁该读 |
|---|---|---|---|
| 1 | `01-vision.md` | 产品愿景、用户群体、成功标准 | 所有人 |
| 2 | `02-roadmap.md` | 分阶段路线图 + **当前状态对照** + 差距分析 | 发起人 / 执行者 |
| 3 | `03-architecture.md` | 双运行时架构、数据流、关键机制 | 执行者 |
| 4 | `04-data.md` | 数据契约与口径（§6/§7 的工程化） | 执行者 |
| 5 | `05-modules/*.md` | 各功能域模块规范（交互/规则/验收） | 执行者 |
| 6 | `06-acceptance.md` | 全量验收清单（P0/P1/P2 + 状态） | 验收人 |
| 7 | `07-backlog.md` | 待办池：按阶段与优先级排布 | 发起人 / 执行者 |
| 8 | `08-changelog.md` | 缺陷修复与变更记录（含根因与防复发） | 所有人 |

## 约定速览

- **三个状态值**：`✅ 已实现` / `🔶 部分` / `⬜ 待办`
- **优先级**：`P0 必须` / `P1 重要` / `P2 可选`（沿用 CLAUDE.md §10）
- **每个功能交付闭环**：模块规范 → 实现 → 单元/行为测试 → 验收项勾选 → 同步回本文档与 `README.md`

## 产物

- 浏览器版：`npm run dev`（IndexedDB 适配器）
- 桌面版：`npm run tauri dev` / `npm run tauri build`
- 发布包：`src-tauri/target/release/bundle/macos/FocusPomodoro.app(.dmg)`（macOS）
